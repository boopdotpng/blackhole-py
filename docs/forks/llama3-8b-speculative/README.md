# blackhole-py-llama3-8b-speculative

Workspace for speculative-decoding experiments, copied from the tuned
`../blackhole-py-llama3-8b` at `f0e0f72`. It now includes a two-token,
weight-sharing verifier with greedy prompt/history-lookup speculation on card 0.
See [speculative decoding results](SPECULATIVE.md). The card-1 measurements below
describe the inherited standard decoder. This copy
has its own Git history, local weights, and virtual environment, with no remote
configured. Development starts on the `speculative-decoding` branch.

Llama 3 8B Instruct, full BF16 weights, batch-one decode on Blackhole.
Validated on card 1: **29.37 tok/s** for short generation and **28.54 tok/s**
for 512-token generation. See [measurements and validation](PERFORMANCE.md).
Built with Meta Llama 3.

## Speculative decoding on card 0

```sh
PYTHONPATH=. .venv/bin/python examples/llama3_speculative.py \
  --device 0 --steps 128 --prompt 'Explain why the sky is blue.'

# Compare against ordinary greedy decoding and require identical tokens.
PYTHONPATH=. .venv/bin/python examples/llama3_speculative.py \
  --device 0 --steps 128 --benchmark --output validation/comparison.json

# Cache-boundary correctness checks and five workload comparisons.
PYTHONPATH=. .venv/bin/python scripts/validate_speculative.py --device 0
```

No additional model or weights are required. Speed depends on how often a
continuation copied from the prompt/history agrees with the target. The default
requires a matching suffix of at least three tokens; `--min-ngram 1` tries more
proposals and can help structured/repetitive output, but can slow general prose.
Prompt ingestion also uses the two-token verifier. The regular
decoder remains available through `examples/llama3.py`.

The 8B baseline was originally copied from the **working tree** of
`../blackhole-py-llama3` (including its uncommitted optimizations). Historical benchmark files and performance notes copied
from that repository describe **Llama 3.2 1B**, not this 8B model.

## Environment and weights

The local `.venv` uses this machine's installed Python packages. From this directory:

```sh
source .venv/bin/activate
export PYTHONPATH=.
python scripts/preflight.py
python -m unittest discover -s tests -v
```

For a fresh environment:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-cpu.txt
PYTHONPATH=. .venv/bin/python scripts/download_weights.py
```

`weights/` contains four safetensors shards (16.06 GB total tensor data),
configuration, tokenizer, chat template, and model license. Weights and the
virtual environment are excluded from Git. Download is resumable and pinned to
`unsloth/llama-3-8b-Instruct` revision
`f3710969eb766fb49d4d1ed3aeabcb03390772bd`. The official Meta repository was gated
for this environment, so this is Unsloth's full BF16 distribution, not a 4-bit
checkpoint. See [model provenance](MODEL.md).

## Run on card 1

```sh
PYTHONPATH=. .venv/bin/python examples/llama3.py \
  --device 1 --safetensor weights --tokenizer weights \
  --prompt 'What is the capital of France? Answer in one short sentence.' \
  --steps 12 --profile
```

`--safetensor` accepts a sharded checkpoint directory or a single safetensors file
with a matching `config.json` alongside it. Model configuration and all 291 tensor
names, shapes, and dtypes are checked before opening a device. The runtime uses
32 layers, 4,096 hidden features, 14,336 MLP features, 128 features per head,
unscaled RoPE, independent embedding/output weights, and an 8,192-token KV cache.
Prompt ingestion runs through the decode kernels one token at a time.

Requirements: compatible `tt-kmd` (>2.9.0, inherited runtime requirement), a
Blackhole P100A/P150 card, approximately 17.14 GB allocated device DRAM, and a
2 GiB pinned host upload area. No firmware binaries or external compiler are
needed; kernels and firmware are generated by the included Python code.

## Validation and measurement

```sh
# CPU reference: loads the full model, no Blackhole access.
PYTHONPATH=. .venv/bin/python scripts/cpu_reference.py

# Fixed-length generation; startup/prompt ingestion excluded, EOS ignored.
PYTHONPATH=. .venv/bin/python examples/benchmark_llama3.py \
  --device 1 --steps 64 --output validation/card1-benchmark.json

# Kernel attribution; run sequentially with other card-1 commands.
PYTHONPATH=. .venv/bin/python examples/profile_llama3.py \
  --device 1 --contexts 32 128 --output validation/card1-profile.json
```

The tuned default uses **88 projection workers**, evenly placed across the chip,
and **32 attention workers**. To select another tested projection worker count,
set `LLAMA_PROJECTION_CORES` before starting Python (80, 88, 96, 104, 112, or 117).
For example, `LLAMA_PROJECTION_CORES=117 PYTHONPATH=. .venv/bin/python examples/llama3.py --device 1 --steps 32 --prompt hello`.

CPU tests check RoPE against Transformers, compact BF16 offsets against the real
tilizer, sharded loading, rejection of incompatible models before device access,
and allocation/lowering/relocation of all 163 launches for nine topology/attention
worker combinations. `validation/cpu-reference.json` records a successful CPU
answer: “The capital of France is Paris.” Card 1 has 117 usable worker cores and eight DRAM banks. The tuned short-context run achieves approximately 29.4 tok/s. Teacher-forced comparison matches all eight
CPU continuation tokens, including EOS, with logit correlation 0.99955–0.99985.
See `validation/card1-correctness.json` and `validation/card1-initial-profile.json`.
See [8B performance results](PERFORMANCE.md) for tuning results and the final validation run.

Model weights now upload in row-major order without host tilization. See
[layout contract and validation](ROW_MAJOR_WEIGHTS.md).
