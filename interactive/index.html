Packer and Unpacker Guide

Blackhole Tensix data movement
GuideUnpackerPacker

The unpacker copies datums from L1 into the math unit's registers (SrcA, SrcB or Dest). The packer copies datums from Dest back to L1. Each one converts formats on the way. Almost everything else in their configuration answers one of three questions:

  1. Where do I read and write? A few counters (X, Y, Z, W) and per-register multipliers form the addresses. Instructions bump the counters, so the next instruction continues where the last one stopped.
  2. Which settings does this instruction use? Most settings exist in several copies called contexts. Each UNPACR or PACR names one, so a kernel can rewrite the next context while the hardware runs the current one.
  3. What happens to each datum on the way? Format conversion, and for the packer optional edge masks, ReLU, thresholding, downsampling, block-float exponent sharing and zero compression.

Unpacker: where it reads

The L1 address doesn't use strides. It counts datums in the shape the tile descriptor gives:

first = ((W0·z_dim + Z0)·y_dim + Y0)·x_dim + X0 count = X1 + 1 − X0 L1 = (base + offset + 1 + digest)·16 + row starts + exponents + first · bytes_per_datum

Base fields hold byte/16 − 1 because the hardware adds 1 for a 16-byte header that tiles don't have.

Unpacker: where it writes

out = (base + Y1·Ystride + Z1·Zstride + W1·Wstride) ÷ output datum size + context dest_address (unpacker 0) row = out / 16 − 4, col = out % 16

The −4 is why blackhole-py sets dest_address to 64. Unpacker 1 writes SrcB; unpacker 0 writes SrcA, or Dest when the context's to_dest bit is set.

Packer: where it reads

bytes = base + Y0·Ystride + Z0·Zstride + W0·Wstride datum = bytes ÷ bytes_per_datum(In_data_format) + context dest_row_offset · 16 count = X1 − X0 + 1 per interface

With all four read interfaces on (intf=0), one PACR reads 4 consecutive Dest rows, as in tt-llk's MOPs.

Packer: where it writes

addr = L1_Dest_addr + 1 + (Y1·Ystride + Z1·Zstride + W1·Wstride)/16 (16-byte units) + Row_start_section_size if compressing + Exp_section_size if Out format bit 1 set

A new address is only taken after a PACR with last (or flush). Until then output is appended, buffered in 16-byte chunks.

Words that mean something specific here

TermMeaning
ADC, countersX/Y/Z/W counters, two channels per unpacker and one set for the packer. Channel 0 is the read side, channel 1 the write side; the two X values are the first and last datum. Each has a carry register for ADDRCR / carry-mode ADDR_MODs.
ContextA copy of the per-move settings. Unpacker 0 has 8 (some fields only 4), unpacker 1 has 2, the packer 4 (selected by PACR cfg_ctx).
State bankA different, coarser copy: the whole shared config space exists twice, and each thread's CFG_STATE_ID picks one. Not modeled here.
ADDR_MOD (packer)Three slots of "after this PACR, add / clear Dest Y, Z and L1 Y, Z". PACR am=N picks one.
Face16×16 datums. A 32×32 tile is 4 faces, stored face after face.
BFPBlock float: 16 datums share one exponent byte. B formats have an 8-bit exponent, A formats 5-bit.
dvalid / bank flipSrcA and SrcB have two banks. The unpacker fills one, then hands it to math (flip=1 or SETDVALID) and moves to the other.
