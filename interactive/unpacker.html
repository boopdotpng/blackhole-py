Configuration

Values before the program runs. CFG lines change them part-way through. Changed fields are orange. Every context whose L1 address is different gets its own generated input tile.

How sure is this?

  • on hw confirmed on card 0 by tests/hw/test_contexts.py: UNPACR cfg_ctx = N reads context N's own L1 base, for N = 0…7.
  • The rest follows the ISA doc's UNPACR functional model, including its Blackhole branches: rows of 32 datums for 16/32-bit formats (16 for 8-bit), SrcA row & 63 with SetOvrdWithAddr, the FP8 E4M3 decode.
  • The ISA doc marks some of what it describes as "no known usage, weak confidence": single-context mode, context counter, upsampling, column shift, compressed input. They are modeled as written there.
  • The L1 address uses the tile descriptor's dimensions (X, Y, Z, W counters), not the channel 0 strides. Channel 1 strides place the output.
  • Not modeled: RowSearch / blobs, the decompression row-start cache and FlushCache, OverlayClear, UNPACR_NOP SETREG, timing and throttling (the SrcA burst check is reported as a warning).
