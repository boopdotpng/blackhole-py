# Blackhole test viewer

Search tests and exact pytest cases, then read the operations emitted by each
RISC. The main listing combines decoded operations with named config assignments.
Select a row for raw RISC-V/Tensix words, every encoded operand, bit positions,
manual explanations, simulator field names, and Python emission locations.
The Instructions view provides a searchable, categorized reference.

From the workspace directory containing `blackhole-py` and `.venv`:

```sh
.venv/bin/python blackhole-py/tools/viewer/server.py --host 0.0.0.0 --port 8765
```

Open **http://tens:8765/** (or the machine's hostname). Omitting `--host` binds
only to `127.0.0.1`. Requires Python 3.12+ and pytest in the same environment
used for blackhole-py. There is no Node dependency or frontend build step.

- Search tests by file, function, or case parameters in the left panel.
- Choose the exact case below it, then a RISC image above the listing.
- Register constant/address setup is hidden by default. “Show RISC-V setup”
  reveals it; runtime arithmetic, memory accesses and control flow remain visible.
  Up/Down steps through visible rows. Jumping directly to a hidden setup
  instruction reveals setup so the exact branch destination can be inspected.
- Search the listing; arrows or Enter/Shift+Enter move between matches.
- Click branch destinations to jump. Select any row for its full decoding.
  Up/Down steps through instructions and updates the detail panel automatically.
- Save `.s` downloads annotated disassembly; it is descriptive text, not a
  reassemblable GNU assembler source file.
- The URL retains the selected case, image, or instruction. Refresh regenerates
  the selected case. Source changes also invalidate the capture cache.

## Capture contract

This is an **offline code viewer**, not a hardware test runner or simulator.
The worker uses pytest's actual collection and parameterization, replaces `bh`
with a capture harness, and instruments `Asm.instructions`. Register allocation,
constant lowering, labels, branch relaxation, and emitted bytes are produced by
the real assembler. Captures include images generated by host-only tests and
all launches reached before the test needs hardware results. Kernel-tab tooltips
identify images that were generated but not submitted before capture stopped.

The default context is explicitly synthetic: P150 topology, eight DRAM banks,
worker index 27, allocation starting at `0x40`, and PCIe MID `0x10000000`.
Allocation shapes use the real Device allocation routines. These are not live
hardware addresses. No results or timings are fabricated. At the first device
read or profiler readback, capture stops and the UI explains that later
host-dependent launches were not captured. Alternate direct PCI-device access
is blocked in the worker. The actual tests are not modified.

Each requested case runs in a fresh subprocess, with a 90-second limit. Two
workers may run concurrently. The server only accepts collected pytest node IDs,
serves its own static files, and caches results in memory. Case generation runs
trusted repository Python, so serve it on your own machine/network.

## Decoding and provenance

- `decode.py` decodes the emitted 32-bit words, including the two-bit rotation
  of inline Tensix instructions. MMIO and MOP-template words remain unrotated.
- RISC-V constant annotations use a fixed-point control-flow analysis. Conflicting
  branch values and changing loop values become unknown. Loads invalidate their
  destination values; device memory is not evaluated. No constant value is
  claimed merely because it appeared earlier in the linear listing.
- `isa.py` supplies actual encoder field widths. Reviewed operand descriptions
  are bundled from `tt-ins-docs`. ttsim fields are shown separately where its
  schema differs from the encoder/manual, including ZEROACC.
- Config fields come from ttsim's Blackhole tables, supplemented by the Blackhole
  `cfg_defines.h` referenced in the ISA manual. Every field identifies its source.
  Both config banks, dual writes, thread windows, byte masks, symbolic addresses,
  semaphore names, and SFPU constant-register identities are labelled. Programmable
  SFPU reset values are explicitly reset values, not inferred current contents.
- `static/behavior.mjs` renders common operations as assignments, transfers,
  arithmetic, waits, or replay operations. Other instructions use the reviewed
  operation title and all decoded fields. Address counters, vector predicates,
  and macro expansion are not simulated. Selecting the row always preserves
  access to the actual encoding and caveats.

Snapshots, source hashes, and third-party attribution live in `data/`.
To regenerate from sibling working trees:

```sh
.venv/bin/python blackhole-py/tools/viewer/update_reference.py
```

This also regenerates the original `tt-ins-docs/lib/instructions.json`. Normal
viewing does not require the sibling docs, ttsim, or tt-metal checkouts.

## Verification

```sh
.venv/bin/python blackhole-py/tools/viewer/capture.py capture --audit \
  --output /tmp/blackhole-viewer-audit.json
```

The capture command's pytest “passed” result means the offline host path reached
its capture boundary or completed; it does **not** mean the hardware test passed.
The JSON distinguishes `boundary`, `complete`, `error`, and `skipped` results.
